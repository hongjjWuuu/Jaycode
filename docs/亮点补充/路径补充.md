
## 概念到代码的映射表

|之前讨论的概念|项目中的对应文件|核心职责|
|---|---|---|
|**Harness Runtime**|`app/harness/runtime.py`|任务上下文、事件时间线、中断恢复|
|**Skill 插件体系**|`app/skills/registry.py` + `app/skills/executor.py`|技能注册、权限校验、沙箱执行|
|**治理化 RAG**|`app/persistence/rag_store.py`|增量索引、版本管理、混合检索、ACL、Gold Set 评测|
|**受控长期记忆**|`app/persistence/memory_store.py`|候选提取、人工确认、冲突检测、过期管理|
|**Benchmark 评测**|分布在 `rag_store.py`（RAG 评测）和 routes 相关接口|黄金数据集、自动计算指标|
|**可视化 Workflow**|`app/graphs/workflow_compiler.py`|画布配置 → LangGraph 可执行图|
|**多 Agent 协作**|`app/graphs/studio_graphs.py`|固定协作图定义|
|**LLM 可观测**|`app/providers/llm_provider.py`|统一调用、Trace、Fallback|

## 你现在该怎么学

你已经建立了概念体系，现在拿着手册的**推荐学习路径**，按三层顺序看代码：

### 第 1 层（先看）：建立 Agent 骨架

按顺序读这 6 个文件，每个文件读的时候，心里默念它对应你学过的哪个概念：

1. **`README.md`** → 全局认知
    
2. **`app/agents/project_tools.py`** → Agent 能干什么（项目理解）
    
3. **`app/agents/code_review_tools.py`** → Agent 能干什么（代码审查）
    
4. **`app/graphs/studio_graphs.py`** → 多 Agent 怎么协作（对应你学的 LangGraph 编排）
    
5. **`app/graphs/workflow_compiler.py`** → 可视化工作流怎么变成可执行图
    
6. **`app/harness/runtime.py`** → **Harness Runtime** 的具体实现
    

### 第 2 层（再看）：系统能力

7. **`app/api/routes/`** → 所有能力怎么按领域暴露出去
    
8. **`app/persistence/rag_store.py`** → **治理化 RAG** 的具体实现
    
9. **`app/persistence/memory_store.py`** → **受控长期记忆** 的具体实现
    
10. **`app/skills/registry.py`** → **Skill 注册中心**
    
11. **`app/skills/executor.py`** → **Skill 执行器**（权限+沙箱）
    
12. **`app/providers/llm_provider.py`** → LLM 统一接入+观测
    

### 第 3 层（最后）：产品层

13-17. 前端入口、类型定义、插件市场、MCP 工具接入

---

## 两个关键提醒

1. **第 1 层最重要**。如果不看懂 `harness/runtime.py` 和 `studio_graphs.py`，后面 RAG、Memory、Skill 都只是孤立模块，你不知道它们是怎么被调度起来的。
    
2. **带着问题读代码**。每打开一个文件，先问自己：这个文件在手册里对应哪个概念？它解决了之前讨论的哪个痛点？这样读比从头到尾硬啃效率高得多。
