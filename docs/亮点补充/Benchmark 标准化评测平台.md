
### 一、要解决的核心痛点

**“只能人工肉眼判断效果，无法量化迭代优化。”**

具体表现：

|问题|后果|
|---|---|
|换了个 LLM 模型，不知道效果变好还是变差|凭感觉选模型|
|调了 RAG 切片策略，不知道 Recall 有没有提升|改了白改，没法验证|
|多 Agent 协作流程改了逻辑，不知道整体影响|不敢动现有流程|
|上线后出问题，只能靠用户投诉才发现|被动响应|

### 二、平台定位

**一个覆盖全链路的自动化评测平台，不是只测 LLM 文本输出。**

评测范围：

LLM → RAG → Workflow → MCP 工具 → 多 Agent 协作

把“评测对象”从单一模型扩展到了整个 Agent 系统的每一个环节。

---

## 三、五大评测对象详解

### 1. LLM 评测

|维度|指标示例|
|---|---|
|文本质量|BLEU、ROUGE、语义相似度|
|指令遵循|格式正确率、约束满足率|
|幻觉检测|事实一致性、引用准确率|
|安全合规|拒答率、有害内容检出率|

### 2. RAG 评测

|维度|指标示例|
|---|---|
|检索质量|Recall@K、Precision@K、MRR、NDCG|
|端到端质量|答案忠实度、上下文相关性|
|切片质量|信息完整度、噪音率|

**核心手段**：内置黄金数据集（Gold Set），标注好标准答案和相关的 Chunk，自动算指标。

### 3. Workflow 评测

|维度|指标示例|
|---|---|
|流程正确性|节点执行顺序匹配率、路径覆盖率|
|决策点准确率|分支选择正确率、条件判断准确率|
|端到端成功率|任务完成率、人工介入率|

**核心手段**：定义工作流的“预期路径”，和实际执行路径对比，偏差即扣分。

### 4. MCP 工具评测

|维度|指标示例|
|---|---|
|调用准确率|工具选择正确率、参数正确率|
|调用效率|调用次数、冗余调用率|
|结果质量|工具返回结果对最终答案的贡献度|

### 5. 多 Agent 协作评测

|维度|指标示例|
|---|---|
|协作效率|消息传递次数、任务完成耗时|
|角色履行|各 Agent 职责完成度|
|整体一致性|多 Agent 输出无冲突、逻辑自洽|

## 四、平台核心能力

### 1. 黄金数据集管理（Gold Set）

人工标注一批“标准问答对 + 期望输出 + 相关文档片段”，作为评测基准。


{
  "query": "项目什么时候立项的？",
  "expected_answer": "2023年11月15日",
  "relevant_chunks": ["chunk_0001", "chunk_0042"],
  "expected_tool_calls": ["search_project_doc"]
}

每次系统变更，自动用这批数据集跑一遍，输出分数变化。

### 2. 自动化评测流水线


代码/配置变更 → 触发评测 → 并行跑各模块评测 → 汇总对比 → 生成评测报告

- **变更触发**：任何模型切换、Prompt 修改、RAG 参数调整、Workflow 逻辑变更
    
- **基线对比**：自动对比变更前后的指标变化
    
- **报告可视化**：雷达图、趋势图、回归检测
    

### 3. 回归检测

新版本指标低于基线超过阈值 → **自动告警，阻断上线**。


if (新版 Recall@5 < 旧版 Recall@5 - 3%) → 告警：RAG 检索质量下降
if (端到端成功率 < 95%) → 阻断：工作流变更可能引入 bug

## 五、解决的实际问题

|场景|没有评测平台|有评测平台|
|---|---|---|
|换 LLM 模型|“感觉快了，但回答好像更啰嗦了？”|语义相似度 +0.05，但指令遵循率 -3%，不换|
|调 RAG 切片大小|“改了，应该好一点吧？”|Recall@5 从 0.82 升到 0.91，有数据支撑|
|改 Workflow 逻辑|“不敢动，万一哪个环节出问题”|自动回归测试通过，放心上线|
|多 Agent 协作优化|“看起来还行，但不知道哪里可以改进”|发现 Agent-B 工具调用冗余率 40%，针对性优化|

## 六、在整体架构中的位置

结合前面的全部设计，这个平台的完整定位是：

> **一个“能看项目、能审代码、能沉淀知识、能编排流程、能做治理”的多 Agent 工程化中台。**

每个模块和评测平台的关系：

|模块|评测平台如何参与|
|---|---|
|**Harness Runtime**|评测工作流执行的可观测性、断点恢复|
|**Skill 插件体系**|评测每个 Skill 的执行效果和安全性|
|**治理化 RAG**|评测检索质量，黄金数据集驱动迭代|
|**受控长期记忆**|评测记忆召回准确性、过期策略有效性|
|**整体 Agent 流程**|端到端评测，保证全局质量不退化|

**Benchmark 平台是让这套中台从“能用”到“敢用、好优化”的关键基础设施。**
