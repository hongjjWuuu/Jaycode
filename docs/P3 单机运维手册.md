# P3 单机运维手册

> 正式运行时 PostgreSQL `jayagent_studio` 是唯一权威库。`data/dev_agent_studio.db` 只保留为迁移历史和恢复对账依据，不能通过修改 `.env` 直接回退使用。

## 日常运行

以 [Jaycode 启动方式](Jaycode%20启动方式.md) 为日常启动入口：先启动 Docker PostgreSQL，再启动 API，最后选择**一种** Worker 模式：独立 Worker，或 `JAYCODE_WORKER_SUPERVISOR_ENABLED=true` 的 API Supervisor。不要同时使用两种模式。

使用以下端点确认运行状态：

- `GET /health`：API 进程存活。
- `GET /ready`：PostgreSQL 与启用的 Supervisor Worker 都可用。
- `GET /metrics`：Prometheus 指标。
- Web 工作台“运营”页：任务队列、审核积压、失败任务与 Worker 状态；仅允许跳转到现有任务审核/取消动作。

## 每日备份

在 Docker Desktop 与 pgvector 容器运行时执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\backup_postgres.ps1
```

脚本在 `data/postgres-backups/` 生成自定义格式备份与脱敏 manifest，限制目录 ACL，使用 `pg_restore --list` 验证，再清理超过 14 天的**严格匹配**历史备份。它不在日志、manifest 或参数中保存数据库密码。

首次确认脚本可用后，才可手动注册每日 03:15 的当前用户任务：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\jaycode-postgres-backup-task.ps1 -Action register
```

注册、查看与删除计划任务都需要操作者显式执行；项目不会自动注册系统计划任务。

## 隔离恢复演练

恢复演练不会覆盖 `jayagent_studio`。它只接受 loopback `postgres` 维护连接，并创建随机 `jaycode_restore_test_*` 库；成功或失败都会尝试删除该测试库：

```powershell
$env:JAYCODE_RESTORE_ADMIN_URL = "postgresql://<user>:<password>@127.0.0.1:5432/postgres"
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\restore_postgres_drill.ps1 `
  -BackupFile .\data\postgres-backups\jayagent_studio-<UTC>.dump `
  -AdminUrl $env:JAYCODE_RESTORE_ADMIN_URL
```

恢复脚本会校验备份格式、恢复所有对象，并确认 public schema 至少有 35 张应用表。不要把连接串写入文档、Git 或终端共享记录。

## 故障处理原则

1. `/ready` 非就绪、Worker 降级或运营页告警时，先停止提交新任务并保留日志、指标和数据库现状。
2. 不要删除 Docker 卷，不要运行 `docker compose down -v`，也不要只修改 `.env` 回退 SQLite。
3. 若需要恢复，先冻结 PostgreSQL 写入，验证最近备份，再在隔离数据库完成恢复演练与数据对账；获得批准后才制定生产恢复窗口。
4. Worker 只是暂时不可用时，任务会保持 `queued`；可恢复 Worker 后在运营页打开任务并使用已有审核/取消流程处理，不进行自动重试。
